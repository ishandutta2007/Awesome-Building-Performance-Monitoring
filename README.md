# Awesome-Building-Performance-Monitoring

# Top Building Performance Monitoring Ecosystem

**Curated List of SaaS Products & Open-Source GitHub Projects**  
*Focused on Building Energy Monitoring, Building Performance, HVAC Optimization, Facility Intelligence, Sustainability & Operational Efficiency*  
**Last updated: August 2026**

This repository tracks notable **SaaS/hosted platforms** and **open-source projects** for **Building Performance Monitoring**. These tools collect, monitor, analyze, and optimize building data including energy consumption, HVAC performance, indoor conditions, equipment health, occupancy, utility costs, carbon emissions, and overall building operational efficiency.

**Examples** include Measurabl, Facilio, BuildingMinds, Enertiv, Switch Automation, BrainBox AI, Aquicore, Spacewell, Dexma, and EnergyCAP.

**Open-source emphasis**: This section is heavily expanded with open-source building-management platforms, energy-management systems, IoT frameworks, building automation platforms, time-series databases, visualization systems, building-data standards, and HVAC optimization projects. Because fully open-source equivalents of commercial building-performance platforms are relatively uncommon, the list also includes strong open-source **building-performance infrastructure and building-energy-management components** that can be combined into a complete self-hosted solution.

Contributions welcome! Open a PR to add/update entries. Keep descriptions factual and link to official sites or repositories.

## Open-Source GitHub Projects

- **[OpenEMS](https://github.com/OpenEMS/openems)**  
  One of the strongest open-source energy-management platforms. OpenEMS provides an IoT stack consisting of **Edge**, **UI**, and **Backend** components for monitoring, controlling, and integrating energy systems and devices. It supports energy storage, photovoltaics, EV charging, heat pumps, time-of-use tariffs, and other energy assets. :contentReference[oaicite:0]{index=0}

- **[VOLTTRON](https://github.com/eclipse-volttron/volttron)**  
  Open-source distributed sensing and control platform designed for buildings and devices. It provides messaging, device drivers, historians, agents, and a web interface for collecting and controlling building data. :contentReference[oaicite:1]{index=1}

- **[VOLTTRON Autonomous Energy Management Software](https://github.com/VOLTTRON/volttron-pnnl-aems)**  
  Open-source building-energy-management application built on VOLTTRON. It provides intelligent control and energy management for HVAC equipment such as rooftop units and heat pumps, with web-based monitoring and demand-response capabilities. :contentReference[oaicite:2]{index=2}

- **[OpenBuildingControl](https://github.com/openbuildingcontrol)**  
  Open-source ecosystem focused on building controls, model-based control, automation, and interoperable building-control workflows.

- **[Brick Schema](https://github.com/BrickSchema/Brick)**  
  Open-source semantic ontology for representing building assets, equipment, sensors, points, spaces, and their relationships. Particularly useful for constructing a building-performance data layer.

- **[Project Haystack](https://github.com/haystack】)**  
  Open building-data modeling ecosystem for describing building automation and IoT data using standardized semantic tagging.

- **[Haystack Java](https://github.com/Project-Haystack/haystack)**  
  Open-source implementation and specification ecosystem for interoperable building-data modeling and exchange.

- **[BACnet Stack](https://github.com/bacnet-stack/bacnet-stack)**  
  Open-source BACnet protocol stack for communicating with building automation and control systems. Useful for collecting HVAC, lighting, meter, sensor, and equipment data.

- **[BACpypes](https://github.com/JoelBender/bacpypes)**  
  Python implementation of BACnet networking protocols that can be used to interface software systems with building automation equipment.

- **[OpenHAB](https://github.com/openhab/openhab-core)**  
  Open-source home/building automation platform with extensive integrations that can be adapted for building telemetry, IoT, automation, and energy monitoring.

- **[Home Assistant](https://github.com/home-assistant/core)**  
  Open-source home automation platform with extensive device integrations, dashboards, automation, energy monitoring, and time-series capabilities. It can also serve as a lightweight building-IoT data layer.

- **[Eclipse IoT](https://github.com/eclipse-iot)**  
  Open-source IoT ecosystem containing protocols, frameworks, and components useful for connecting building sensors, gateways, devices, and cloud systems.

- **[Eclipse Ditto](https://github.com/eclipse-ditto/ditto)**  
  Open-source digital-twin framework for representing physical devices and assets digitally, useful for building equipment and smart-building applications.

- **[ThingsBoard](https://github.com/thingsboard/thingsboard)**  
  Open-source IoT platform providing device management, telemetry ingestion, dashboards, rules, alarms, and analytics. It can be used as a building-performance monitoring backend.

- **[Mainflux](https://github.com/mainflux/mainflux)**  
  Open-source IoT platform for connecting devices, collecting telemetry, managing data, and building IoT applications.

- **[EdgeX Foundry](https://github.com/edgexfoundry/edgex-go)**  
  Open-source edge-IoT framework supporting device connectivity, data ingestion, rules, and processing. Useful as an abstraction layer between building devices and analytics platforms.

- **[OpenRemote](https://github.com/openremote/openremote)**  
  Open-source IoT and building automation platform supporting asset management, sensors, rules, dashboards, energy management, and automation.

- **[Fledge](https://github.com/fledge-iot/fledge)**  
  Open-source industrial IoT framework for collecting and processing data from sensors and industrial equipment at the edge. It can be adapted for building equipment and energy telemetry.

- **[Grafana](https://github.com/grafana/grafana)**  
  Open-source observability and visualization platform widely useful for building dashboards showing energy consumption, HVAC metrics, indoor conditions, equipment performance, and KPIs.

- **[InfluxDB](https://github.com/InfluxCommunity/InfluxDB)**  
  Time-series database suitable for storing high-frequency building sensor, energy-meter, HVAC, and IoT telemetry.

- **[TimescaleDB](https://github.com/timescale/timescaledb)**  
  PostgreSQL extension optimized for time-series workloads, useful for building energy and equipment telemetry.

- **[Prometheus](https://github.com/prometheus/prometheus)**  
  Open-source monitoring and time-series platform that can be adapted for infrastructure and building-system metrics.

- **[Telegraf](https://github.com/influxdata/telegraf)**  
  Open-source telemetry collection agent supporting numerous inputs and outputs, useful for collecting building-system and IoT data.

- **[Node-RED](https://github.com/node-red/node-red)**

- **[OpenEnergyMonitor](https://github.com/openenergymonitor)**

- **[City Energy Analyst](https://github.com/architecture-building-systems/CityEnergyAnalyst)**

- **[MPCPy](https://github.com/lbl-srg/MPCPy)**

**Frameworks for building custom building-performance monitoring systems**: Combine **BACnet / Modbus / MQTT** for building-device connectivity, **VOLTTRON / OpenRemote / ThingsBoard** for IoT and control, **Brick / Haystack** for semantic modeling, **InfluxDB / TimescaleDB** for time-series storage, and **Grafana** for visualization.

For a more advanced energy-optimization stack, combine **OpenEMS**, **VOLTTRON**, **EnergyPlus**, **OpenStudio**, and **BOPTEST** with a machine-learning or model-predictive-control layer.

A potential open-source building-performance architecture can look like:

**Building Sensors / Meters / BMS → BACnet / Modbus / MQTT → Edge Gateway → VOLTTRON / OpenRemote → Time-Series Database → Brick / Haystack Semantic Layer → Grafana → Analytics / Fault Detection / Optimization**

For an energy-management-focused architecture:

**Smart Meters + PV + HVAC + Battery + EV Chargers → OpenEMS Edge → OpenEMS Backend → Time-Series Storage → Dashboard → Optimization / Control**

For an AI building-optimization pipeline:

**BMS Data → IoT Gateway → Time-Series Database → Building Semantic Model → Feature Engineering → Fault Detection → Energy Forecasting → HVAC Optimization → Automated Control**

One of the strongest direct open-source foundations is **OpenEMS**, which explicitly provides Edge, UI, and Backend components for monitoring and controlling energy systems and supports devices such as energy storage, photovoltaics, EV charging, and heat pumps. :contentReference[oaicite:4]{index=4}

**VOLTTRON** is particularly valuable for commercial-building applications because it is designed around distributed sensing and control and provides device drivers, historians, an agent framework, a message bus, and a web UI. :contentReference[oaicite:5]{index=5}

The **VOLTTRON AEMS** project demonstrates how this foundation can be extended into an actual building-energy-management application, including HVAC optimization, automated diagnostics, demand response, and a web interface. :contentReference[oaicite:6]{index=6}

The open-source ecosystem therefore supports several layers:

**Building Connectivity:**  
BACnet + Modbus + MQTT + OPC UA

**Edge / Control:**  
VOLTTRON + OpenRemote + OpenEMS + EdgeX

**Semantic Building Data:**  
Brick + Haystack

**Storage:**  
InfluxDB + TimescaleDB + PostgreSQL

**Visualization:**  
Grafana + custom web applications

**Simulation:**  
EnergyPlus + OpenStudio + Modelica Buildings Library

**Optimization / AI:**  
BOPTEST + MPCPy + Sinergym + custom ML models

This makes it possible to build a self-hosted alternative to many components found in commercial platforms such as **Facilio, Enertiv, Switch Automation, BrainBox AI, Aquicore, Spacewell, DEXMA, and EnergyCAP**, although a commercial-grade deployment will generally require substantial integration, building-system commissioning, hardware connectivity, data engineering, analytics, and operational expertise.

## How to Contribute

1. Fork the repo.
2. Add/edit entries in `README.md` (follow existing format).
3. Include: name, link, 1–2 sentence description, and whether it's SaaS or open-source.
4. Prefer projects with active development and publicly accessible source code.
5. For infrastructure projects, clearly identify them as **building-performance building blocks** rather than complete monitoring platforms.
6. Include the relevant protocols, standards, or building systems supported when useful.
7. Note when a project is archived, experimental, research-oriented, or primarily a simulation tool.
8. Submit PR with a short explanation.

Star the repo if you find it useful!

## Disclaimer

- This is a **community-curated** list — not exhaustive and not an endorsement.
- Commercial building-performance platforms differ significantly in scope: energy monitoring, BMS integration, HVAC optimization, fault detection, sustainability, facility management, digital twins, ESG reporting, and utility management.
- Many open-source projects listed here are **building blocks rather than direct replacements** for commercial building-performance platforms.
- Open-source building-management deployments may require additional hardware gateways, sensors, BMS integration, cybersecurity controls, data storage, dashboards, and analytics.
- Building-control software should be deployed with appropriate safety mechanisms and engineering validation before being connected to operational HVAC or other critical building equipment.
- Energy simulations such as EnergyPlus and OpenStudio should not be confused with real-time building monitoring systems.
- Always verify current licensing terms, project activity, security posture, hardware compatibility, and production readiness before deployment.
